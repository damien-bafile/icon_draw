## Design Specificity Verdict

**LLM assessment**: Core-authored, chrome-generic. The grid renders the exact C data model (5 columns = 5 bytes, bit indices 0–6, "bit 0 = top row" caption) and the deliverable is genuinely C source — this is not a bitmap editor that could ship anywhere. But the specificity stops at the grid + caption; the Comment/Clear/Copy furniture is interchangeable, and nothing signals the embedded context beyond the byte format (no OLED-scale glyph preview, no per-column byte linkage in the output).

**Deterministic scan**: Detector returned `[]` (0 findings), exit 0 — it reads HTML/CSS and this is Tkinter, so no rules apply. No false positives.

**Visual overlays**: Skipped — native Tkinter app, no web surface, no HTML, no dev server, no browser automation path.

## Overall Impression

The grid is now genuinely authored for this product — undo/redo, a real keyboard path, and the data model drawn on the canvas are all high-quality work. The gap has shifted from "does it work" to "is the product moment loud enough": the exported C line — the entire point of the tool — is the quietest, dimmest element in the window, and Copy is visually identical to Clear. 26/40 is a solid Acceptable that's one emphasis pass away from Good.

## What's Working

1. **Live output preview wired end-to-end** (main.py:94-99, grid.py:167-169): every cell toggle and comment keystroke recomputes the C line instantly — "trustworthy at a glance" delivered structurally, not decorated.
2. **The grid renders the data model itself** (grid.py:190-209): column/bit gutter indices on the canvas make the byte layout visible at the source — cheap, high-specificity design.
3. **Disciplined state handling** (grid.py:43-95): snapshot undo/redo with 50-entry cap, redo cleared on new action, no-op-guarded `clear()` — above the bar for a utility this size.

## Priority Issues

**[P1] Silent output truncation** — output_entry width=42 in a non-resizable window (main.py:136-143); a comment ≳20 chars pushes the line past the visible field and the readonly entry scrolls quietly. Why: "correctness by construction" is the brand; a truncated, unverifiable preview can paste wrong bytes into a font table. Fix: widen, allow window resize, or cap comment length visibly. Suggested command: **harden**.

**[P1] Keyboard path is invisible and undocumented** — all grid shortcuts (grid.py:50-57) and undo/redo binds (main.py:146-151) exist with zero in-UI trace; PRODUCT.md still claims "pointer-only" (now stale). Why: the shipped accessibility/power-user feature is undiscoverable (heuristic 10 = 1). Fix: one quiet hint line under the grid or tooltips. Suggested command: **document**.

**[P1] Drag-to-toggle erases strokes on re-cross** — _on_drag/_toggle_at (grid.py:107-119) toggle every cell passed, so drawing a letter's stroke across a lit cell deletes it. Why: glyph drawing is mostly additive; this fights the user mid-draw (heuristic 7, emotional valley). Fix: default drag to paint-on, erase via right-drag/modifier; keep click = toggle. Suggested command: **shape**.

**[P2] Silent comment sanitization** — _sanitize_comment (exporter.py:17-27) rewrites `*/` and newlines with no feedback. Why: pasted C differs from typed text → trust erosion where the tool promises correctness. Fix: transient "comment sanitized" note or pre-copy confirmation. Suggested command: **clarify**.

**[P2] Weak, leaky copy moment** — flash_status (main.py:118-121) is small, bottom-positioned, race-prone (duplicate `after` timers clear the second flash), raw `TclError` surfaced (main.py:128), and copy_to_clipboard (exporter.py:30-36) leaks a Tk root if clipboard_append raises. Why: the product's peak moment is under-delivered. Fix: status adjacent to Copy, dedupe timers, humanize errors, guard root.destroy(). Suggested command: **polish**.

## Persona Red Flags

**Alex (power user)**: The whole product is "the fast path from grid to C," yet export is mouse-only — no ⌘Enter on the output — and drag-crossing erases strokes, so his strokes need mouse-surgery. He'd find arrows/Space/C/⌘Z eventually, but nothing hints they exist. The fixed 42-char window caps his comments. Fails: Copy button (main.py:132) as the only export path; _on_drag (grid.py:107).

**Sam (accessibility-dependent)**: The grid is a tk.Canvas — screen readers get nothing; on/off are color/luminance-only (no pattern cue); the focus cursor is a 1–2px outline in SUBTEXT0 when unfocused, easy to lose against SURFACE0 cells; status text is transient. The keyboard path is a real win but undiscoverable and unannounced. Fails: cursor draw (grid.py:210-223), flash_status (main.py:118-121), status position (main.py:144).

**Riley (stress tester)**: Pasting a long comment → silent truncation (worst case: copies a line he couldn't fully see). Copy twice fast → first `after` timer wipes the second confirmation. Copy on a machine with clipboard failure → raw `TclError` + leaked root each retry. Toggle-on/toggle-off pushes no-op history entries so undo steps through dead states. Fails: output_entry (main.py:136), flash_status (main.py:121), copy_to_clipboard (exporter.py:30-36), _push_history (grid.py:73-77).

## Minor Observations

- PRODUCT.md §Accessibility is stale — documents "no keyboard path / pointer-only," contradicting shipped code.
- A truly empty grid copies five zero bytes with no "empty glyph?" guard.
- Title "5x7 Font Draw" vs package `icon-draw`; naming drift.
- Comment entry (24) and output (42) widths independently chosen; a 24-char comment already overflows the output field.
- Readonly output uses MANTLE + SUBTEXT0 — deliberately subdued, but that's the hero element.
- _on_drag sets self._cursor to every cell passed, leaving the cursor outline mid-glyph after release.
- No Enter-to-export on the comment field.

## Questions to Consider

1. If "export is the product," why is the exported line the quietest element, and why is Copy, the one true action, visually identical to Clear?
2. Should drag be additive-only (paint) by default with erase behind a modifier — does the current toggle ever match how a person actually draws?
3. Is truncation the honest behavior when the comment overflows the fixed output field, in a tool whose promise is correctness-by-construction? Should the window resize instead?
4. Is clipboard the right terminus, or would a per-glyph clipboard stack / direct-to-editor insert serve a multi-glyph font-table session better?
5. Could the grid show its own byte more directly — hovering a column reveals its `0x..` byte in the output — removing the working-memory translation entirely?
