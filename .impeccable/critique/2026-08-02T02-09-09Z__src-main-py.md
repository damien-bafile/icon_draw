# Priority Issues

1. **[P1] Ghost-cell fix is incomplete; the bug reproduces on an empty grid.** grid.py:253 returns False before _cancel_active_press() runs. Trace: empty grid → press-hold a cell → tap c → clear() returns False, _press_cell survives → release toggles the held cell ON. CONFIRMED: cell lights.
   - **Fix**: call `_cancel_active_press()` before the early return in `clear()`.
   - **Suggested command**: /impeccable harden

2. **[P1] Accessibility readout desyncs during arrow-key navigation.** With grid focus, the canvas's own arrow handlers return "break" and never refresh; root-level _move/refresh_grid_info is skipped. CONFIRMED: cursor moves to (0,1), readout still shows (0,0).
   - **Fix**: refresh the readout from the canvas arrow path too (move_cursor should notify, or the canvas arrow handler should call the refresh).
   - **Suggested command**: /impeccable harden

3. **[P2] Primary action buried, destructive neighbor, hierarchy inverted.** Copy is button #5, 8px from Clear; the C line sits at the bottom in a flat field while the Comment input gets 14pt mono at the top. For "Export is the product", the surface argues the opposite.
   - **Fix**: move Copy to the right edge / give the C line a bordered code-panel treatment; separate the destructive control.
   - **Suggested command**: /impeccable layout

4. **[P2] Unbounded window growth.** fit_output has no cap; the window physically grows to fit, breathing while typing and pushing output off small displays (the screen clamp exists only for tooltips).
   - **Fix**: clamp entry width + scroll, or cap with ellipsis + full line in a tooltip.
   - **Suggested command**: /impeccable adapt

5. **[P2] Command clutter + no close guard.** "Example" is a demo affordance wearing a primary-toolbar slot, silently overwriting work. No dirty-flag/confirm-on-close — undo is in-memory only. 4 persistent grey text rows + 5 buttons compete with the canvas for "dead simple".
   - **Fix**: fold Example away, consolidate hint rows, add a title-bar dirty indicator.
   - **Suggested command**: /impeccable distill

# Questions to Consider

- Export is the product — so why is the C line the smallest element at the bottom while the Comment field gets 14pt mono at the top?
- Clear sits 8px from Copy and is one bare keypress (c). For a tool whose only asset is 35 cells of work, is a one-key nuke with a thin status reassurance the right risk posture?
- Bit 0 = top is this tool's convention — a large slice of the 5x7 OLED world expects bit 7 = top. Would a one-click bit-reverse make the export trustworthy for both camps, or is that ceremony?
- If grid_info_var is Sam's whole a11y story and it desyncs on arrow keys, is a text label the right vehicle at all — or does the canvas need a genuine screen-reader layer?
- The window physically grows to fit your comment, and the tooltip clamps to screen bounds but the entry doesn't. How does "trustworthy at a glance" survive when the output can drift off a 1366px laptop screen?
- A user draws, copies, then draws more — the clipboard silently holds stale bytes. Is "correctness by construction" compatible with never telling the user the clipboard is lying?
