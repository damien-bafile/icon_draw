# Design Specificity Verdict

**LLM assessment**: Grounded, not interchangeable. Column-major packing, one byte per column, bit 0 = top row, five bytes left-to-right — that is exactly the u8g2/u8x8 and Adafruit-GLCD glyph table format that firmware devs paste into character-set libraries. The gutter indices (0-4 top, 0-6 left) map 1:1 onto byte and bit positions, so the visual grid IS the data layout. Comment sanitization (`*/` → `* /`) is a genuine C-correctness concern only an embedded tool would care about. This could not be retitled for photo editing or vector drawing without rewriting everything. Weakness: the tool never renders the glyph at its native 5x7 proportion, so the "giant-cell" view is the only view — the user can't see what the OLED will actually show.

**Deterministic scan**: `[]` findings, exit code 0. The detector is HTML/CSS-oriented and cannot model Tkinter geometry, fonts, or contrast, so an empty result does not indicate the UI passes any critique — it means the detector found nothing it can evaluate.

**Visual overlays**: none — this is a native Tkinter desktop app, not a browser-viewable target. No overlay injection applies.

# Overall Impression

The keyboard model and sticky-status invariant landed cleanly and this is now a genuinely polished single-glyph tool — the score rose to the "Excellent" band. The strongest remaining risks are two: a real correctness bug (c-key ghost cell) and a self-inflicted regression (the output-width cap that hides the very line users came to verify).

# What's Working

1. **Global keyboard model with a correct guard.** Root-level bindings + canvas `"break"` means arrows/space/c work everywhere except exactly where they'd type, and it never double-fires. This is the interaction spine the tool needed, and it's clean.
2. **The sticky-status invariant is provably correct.** "Copied" is cleared iff the output diverges from the copied line. The app's central claim — "what I copied is what I see" — is now structurally guaranteed, not best-effort.
3. **Self-revealing affordances.** Tooltips on all 5 buttons, a legend that names every accelerator, and disabled-state history make the tiny feature set discoverable without dialogs.

# Priority Issues

1. **[P1] Silent corruption: `c` during a click-hold toggles a ghost cell.**
   - **Why it matters**: press-and-hold a cell (no motion), tap `c`, release. `clear()` empties the matrix and pushes history; `_on_release_left` sees `_dragged=False` and toggles `_press_cell` on the now-empty grid. Result: "Cleared" flash, then one mysteriously lit cell — silently wrong glyph bytes in a tool whose entire purpose is correct bytes.
   - **Fix**: root `c` binding should also set the grid's drag state, or `clear()` should invalidate `_press_cell`.
   - **Suggested command**: /impeccable harden

2. **[P1] The 72-char output cap broke "trustworthy at a glance."**
   - **Why it matters**: `fit_output` truncates the preview for any real-world comment ("medium weight, used in boot screen"), and the readonly entry scrolls horizontally with no affordance that it's clipped. The product principle "output trustworthy at a glance" is now defeated for the most common case. Workaround (copy and inspect elsewhere) exists but this was the one place the user was supposed to verify before the clipboard.
   - **Fix**: make the output area non-scrolling and expand the window to fit the full line (or wrap to a monospace block), rather than capping.
   - **Suggested command**: /impeccable layout

3. **[P2] Bare Return no longer toggles when focus leaves the grid.**
   - **Why it matters**: canvas binds `<Return>` but root binds only Cmd+Return. Tab onto Undo, press Return → you get an undo, not a cell toggle, while space does toggle. Two "toggle" keys that behave differently by focus is an inconsistency a mid-flow user trips on.
   - **Fix**: pick one toggle key and make it consistent; if space is the global toggle, bind Return consistently too or drop the canvas Return binding.
   - **Suggested command**: /impeccable clarify

4. **[P2] The grid canvas is inaccessible.**
   - **Why it matters**: no screen-reader path to cell state, cursor position, or the flash messages (which also self-clear in 1.8s). Keyboard input works, but there is zero non-visual feedback that input did anything.
   - **Fix**: add an accessible label/status description of cursor position and cell state; announce state changes to the accessibility layer.
   - **Suggested command**: /impeccable harden

5. **[P2] Tooltips overflow the window.**
   - **Why it matters**: `_ToolTip` anchors x+width+6 to the right of the button; Copy is the last widget before the status label and the buttons sit at the window's bottom row — on smaller screens the tip is clipped off the right/bottom edge. The tip also vanishes the moment the pointer leaves the button, so a long tip can't be read.
   - **Fix**: anchor tooltips above the button (or clamp to screen bounds), and add a small linger delay.
   - **Suggested command**: /impeccable polish

# Persona Red Flags

- **Alex (Power User)**: The 72-char cap. Alex does 20 glyphs a session and eyeballs the C line between every copy. With a comment longer than a few words, the preview is clipped and Alex must scroll a readonly entry or copy-then-peek — the tool's single most-used verification surface just went fuzzy. Also: Return-vs-space inconsistency breaks Alex's muscle memory when focus drifts.
- **Jordan (First-Timer)**: The three stacked hint lines and the three mouse modes. Jordan draws an "A," sees it light up lavender, presses Copy, and is done — but has never learned that right-drag erases, so correcting a mistake means clicking each cell twice. The right-drag affordance is the least-discoverable interaction in the product and it's only one hint-line token deep.
- **Sam (Accessibility)**: Focus lands on the grid canvas, but VoiceOver reads a canvas as an opaque blank. Sam can arrow around (root bindings work) but gets no announcement of cursor position or cell on/off, and the status flashes are visual-only and 1.8s. Every state change in this tool is delivered through a modality Sam cannot perceive.

# Minor Observations

- Double redo is wired (Cmd+Y and Cmd+Shift+Z) but only Cmd+Shift+Z is advertised — harmless, slightly untidy.
- `_sticky_status` stores the text it no longer uses (only the non-None check matters); dead-ish state.
- The window is resizable but nothing scales — the grid stays fixed and the output entry eats the extra width; resizing invites the expectation of layout that never comes.
- Clear and c get no visual warning color; the destructive control is a plain button next to an accent Copy. Undo makes this acceptable, but the tooltip/flash are the only cost signals.
- The "C source:" header sits a full row away from the legend that explains its byte order; the mapping fact and the output it governs are visually separated.
- Empty-glyph copy uses SAPPHIRE vs GREEN for normal copy — a good, subtle distinction.
- No tooltip on the grid, comment field, or output entry — the semantics live only in the legend line.

# Questions to Consider

- If the export is the product, why is the C line a scrollable readonly entry instead of a non-scrolling monospace block, and why can't you ever see the whole line and the whole glyph at once?
- A 5x7 glyph on 40px cells is a toy at the wrong aspect for what the OLED shows — should there be a native-resolution mini-render so WYSIWYG is true?
- You committed to "space toggles" globally but left bare Return as a focus-dependent second toggle — why keep two keys that mean different things by focus? Pick one and say so in the hint.
- Given the c-key ghost-cell, how many more rounds until a destructive global shortcut earns a per-action guard — or should `c` require being in grid focus, like the drag it can corrupt?
- Does a persistent "Copied to clipboard" outliving the moment actually serve the user, or is it a sticky-toast trap that should quietly expire on focus-loss, with the flash as the real feedback?
- The tool has two invisible modes (paint/erase) separated only by mouse button — when you already have a mode-free action set (space toggles both ways), is right-drag erase adding capability or adding a second mental model you must keep advertising forever?
